## [00:00 - 02:00] ИНТРО — Проблема

### Что говорить

> У тебя есть ИИ-агент. Claude Code, Codex, Gemini CLI — неважно. Ты с ним работаешь час, два, три. И в какой-то момент он начинает тупить. Забывает, что ты ему говорил в начале. Повторяет одни и те же ошибки. Путает файлы.

> Почему? Потому что у любого ИИ-агента есть контекстное окно. Это его оперативная память. У Claude — 200 тысяч токенов. Звучит много, но при активной работе это 2-3 часа. И когда окно заполняется — агент начинает терять информацию.

> Но есть 7 команд, которые решают эту проблему. Я использую их каждый день в своём агенте ClaudeClaw. И сегодня я покажу каждую из них — что делает, когда использовать, и как внедрить к себе за 5 минут.

> Плюс — внизу в описании ссылка на 7 файлов. Скачиваешь, скидываешь своему агенту, пишешь один промпт — и команда работает. Без программирования.

### Что на экране

- Заставка канала (2-3 секунды)
- Терминал с работающим Claude Code (показать длинную сессию)
- Графика: шкала контекстного окна 0% → 100% с пометками "работает хорошо" → "начинает тупить" → "забывает всё"

### [02:30] Команда 1: /checkpoint

#### Что говорить

> Checkpoint — это как нажать Ctrl+S для памяти агента. Ты работал два часа, настроил парсер, починил баг, принял решение по архитектуре. Пишешь "checkpoint" — и агент сохраняет 3-5 ключевых итогов в долговременную память.

> Куда сохраняет? В два места. Первое — SQLite база данных. Оттуда данные автоматически подгружаются в каждую новую сессию. Второе — Obsidian. Это как дневник агента — можно потом открыть и посмотреть, что было в каждой сессии.

> Когда использовать? После каждой значимой задачи. Перед переключением темы. В конце рабочего блока. Я делаю checkpoint каждый час-два.

#### Демо на экране

1. Показать терминал с Claude Code
2. Написать: `checkpoint`
3. Показать ответ агента (3-5 bullet points)
4. Открыть Obsidian — показать сохранённый файл в Sessions/
5. Открыть SQLite — показать запись в таблице memories (необязательно, если сложно)

#### Пример диалога для демо

```
Пользователь: checkpoint

Агент: Checkpoint сохранён — SQLite + Obsidian.
• Настроен MCP сервер для Firecrawl — парсинг работает
• Добавлен формат /schedule в систему планировщика
• Исправлен баг с таймзоной в schedule-задачах (UTC → MSK)
```

### [04:30] Команда 2: /dream

#### Что говорить

> Dream — это дефрагментация памяти. Как сон для мозга.

> Представь: ты неделю работаешь с агентом. Каждый день делаешь checkpoint. Накопилось 30-40 записей. Половина — устаревшая. Часть — дубликаты. Три записи говорят одно и то же разными словами.

> Пишешь "dream" — и агент проходит по всей памяти. Удаляет мусор. Объединяет дубликаты. Если 5 записей про одну тему — сжимает в один чёткий паттерн. Было 40 записей — стало 25, но каждая полезная.

> Я запускаю dream раз в неделю. Иногда ставлю на автоматическое расписание — каждое воскресенье в 3 ночи. Но об автоматизации — позже.

#### Демо на экране

1. Показать файл agent-memory.md в Obsidian (до dream — много записей)
2. Написать: `dream`
3. Показать отчёт агента (было X, стало Y, удалено Z)
4. Показать файл agent-memory.md после dream (чище, компактнее)

#### Пример диалога для демо

```
Пользователь: dream

Агент: Консолидация завершена.
• Было: 43 записи
• Стало: 28 записей
• Удалено: 11 устаревших (разовые баги, старые пути)
• Обобщено: 4 группы → 4 паттерна
  - 5 записей о форматах экспорта → 1 правило
  - 3 записи о работе с API → 1 паттерн
```

### [07:00] Команда 3: /newchat

#### Что говорить

> Newchat — это перезагрузка с сохранением. Комбинация двух действий: сначала checkpoint (сохраняет итоги), потом сброс контекстного окна до нуля.

> Зачем? Контекстное окно конечное. Когда оно заполняется на 80-90%, агент уже работает хуже — забывает детали, путает инструкции. Newchat обнуляет контекст, но всё важное уже сохранено в памяти и подгрузится в новую сессию.

> Важный момент: newchat — это не потеря данных. Это перезагрузка компьютера. Все файлы на месте, все программы установлены. Просто оперативная память очищена.

> Когда использовать? После 3-4 compactions. При смене темы. Когда convolife показывает 80%+. Или просто — когда чувствуешь, что агент стал отвечать хуже.

#### Демо на экране

1. Показать `/convolife` → 85% used
2. Написать: `newchat`
3. Показать ответ: "Checkpoint сохранён. Начни новую сессию."
4. Начать новую сессию — показать, что агент помнит ключевые факты

#### Пример диалога для демо

```
Пользователь: convolife
Агент: Context: 85% used — ~30k tokens remaining

Пользователь: newchat
Агент: Checkpoint сохранён. Начни новую сессию — контекст сохранён.
• Настроен планировщик cron-задач
• Добавлены 3 новых команды в агента
• Формат раздаточных материалов утверждён

[Новая сессия]
Пользователь: Что мы делали в прошлой сессии?
Агент: В прошлой сессии вы настроили планировщик cron-задач,
добавили 3 новых команды и утвердили формат раздаточных материалов.
```

### [12:30] Команда 5: /compact

#### Что говорить

> Compact — это сжатие контекста без перезагрузки. Когда convolife показывает 60-70%, но задача ещё не закончена — compact.

> Что происходит: агент берёт всю историю разговора, сжимает её в краткое резюме, и продолжает работу. Контекст освобождается на 50-70%, но нить задачи сохраняется.

> Важный нюанс. Compact — это не бесконечный ресурс. Каждое сжатие теряет детали. Первый compact — почти без потерь. Второй — уже заметно. Третий-четвёртый — агент может забыть важные нюансы. После 3-4 compactions — лучше делать newchat.

> И ещё одна вещь. Не путайте compact, clear и newchat. Compact — сжимает, задача продолжается. Clear — стирает всё, чистый лист. Newchat — checkpoint + новая сессия. Три разных инструмента для трёх разных ситуаций.

#### Демо на экране

1. Показать `/convolife` → 67% used
2. Написать: `compact` (или `/compact`)
3. Показать, что контекст сжался
4. Написать: `convolife` → 25% used (примерно)
5. Показать таблицу сравнения compact / clear / newchat (графика)

#### Пример диалога для демо

```
Пользователь: convolife
Агент: Context: 67% used — ~66k tokens remaining

Пользователь: /compact
Агент: Контекст сжат. Продолжаем работу.
Резюме: работаем над парсером Instagram Reels,
добавляем поддержку карусельных постов.

Пользователь: convolife
Агент: Context: 24% used — ~152k tokens remaining
```

### [15:30] Команда 6: /schedule create

#### Что говорить

> В исходной версии заметки здесь был /loop. Но в CodexClaw отдельной команды /loop сейчас нет.

> Вместо этого у нас есть /schedule. Он создаёт задачу по cron-расписанию через встроенный планировщик.

> То есть вместо "/loop 5m проверь статус деплоя" мы используем "/schedule create */5 * * * * проверь статус деплоя".

> Да, это менее разговорный формат, зато он уже реально внедрён в проект и работает через scheduler.

#### Демо на экране

1. Написать: `/schedule create */5 * * * * проверь статус PR #47`
2. Показать первый результат
3. Подождать (или смонтировать) второй результат через 5 минут
4. Написать: `/schedule list`

#### Пример диалога для демо

```
Пользователь: /schedule create */5 * * * * проверь статус PR #47

Агент: Scheduled task created: task_001
Risk: review
Policy: default
```

### [17:30] Команда 7: /schedule list / pause / resume / delete

#### Что говорить

> В заметке раньше это было как отдельный Cron с командами CronCreate, CronList и CronDelete. В CodexClaw всё это собрано в одну семью: /schedule.

> У меня настроено 5-6 cron-задач. Каждое утро в 9:00 — агент проверяет Gmail и Calendar, собирает дайджест и отправляет мне. Каждый понедельник в 10:00 — анализирует видео конкурентов за неделю. Каждое воскресенье в 3 ночи — запускает dream, консолидирует память.

> Основные действия такие: /schedule create, /schedule list, /schedule pause, /schedule resume, /schedule delete.

> Для расписания используется стандартный формат cron. Не пугайтесь, это проще чем кажется. 5 цифр: минуты, часы, день месяца, месяц, день недели. Звёздочка — значит "любой". "0 9 * * *" — каждый день в 9:00. "0 10 * * 1" — каждый понедельник в 10:00.

> В раздаточном файле я дал таблицу с самыми частыми паттернами — скачаете и будет перед глазами.

#### Демо на экране

1. Создать задачу: `/schedule create 0 9 * * * проверь Gmail и отправь дайджест`
2. Показать подтверждение
3. Показать список задач (`/schedule list`)
4. Удалить одну задачу (`/schedule delete <taskId>`)

#### Пример диалога для демо

```
Пользователь: /schedule create 0 9 * * * проверь Gmail, Calendar и отправь дайджест

Агент: Scheduled task created: task_001
Risk: review
Policy: default

Пользователь: /schedule list

Агент: Активные задачи:
#001 | active | review | 0 9 * * * | 2026-04-21T09:00:00.000Z
#002 | active | safe | 0 3 * * 0 | 2026-04-26T03:00:00.000Z

Пользователь: /schedule delete task_002
Агент: Scheduled task deleted: task_002
```

### [20:00] Старая схема vs формат CodexClaw

#### Что говорить

> Если коротко: в старой схеме были отдельные Loop и Cron. В CodexClaw мы не плодим отдельные команды и используем один вход через /schedule.

> Для видео можно коротко проговорить так: раньше я бы разделил это на loop и cron, а в CodexClaw это всё закрывается одной семьёй команд через /schedule.

#### Важный нюанс: Cron vs Schedule — в чём разница?

Это частый вопрос, поэтому разберём отдельно.

- В заметке было: Loop + Cron
- В CodexClaw сейчас: `/schedule create`, `/schedule list`, `/schedule pause`, `/schedule resume`, `/schedule delete`
- То есть смысл тот же, но интерфейс один и он уже внедрён

Таблица сравнения:

| | Старая заметка | CodexClaw |
