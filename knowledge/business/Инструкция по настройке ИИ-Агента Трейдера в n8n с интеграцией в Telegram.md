# Инструкция по настройке ИИ-Агента Трейдера в n8n с интеграцией в Telegram

Данный документ содержит пошаговую инструкцию по импорту и настройке рабочего процесса (workflow) ИИ-Агента Трейдера в платформе n8n. Агент разработан в соответствии с вашими требованиями к позиционной торговле на Московской бирже (MOEX), включая многофакторный анализ и механизм контроля неопределенности.

## 1. Обзор рабочего процесса (Workflow)

Рабочий процесс **n8n_trader_agent_workflow.json** состоит из двух основных ветвей:

| Ветвь | Триггер | Назначение |
| :--- | :--- | :--- |
| **Автоматический отчет** | Cron (ежедневно в 09:30 МСК) | Ежедневный анализ 10 самых ликвидных акций MOEX и отправка торговых идей в Telegram. |
| **Режим "Вопрос-Ответ"** | Webhook (URL-адрес) | Позволяет отправлять агенту запросы или сигналы из TradingView для немедленного анализа и корректировки данных. |

## 2. Подготовка и необходимые компоненты

Для успешной настройки вам потребуются следующие компоненты:

1.  **Платформа n8n:** Установленный и работающий экземпляр n8n.
2.  **Telegram Bot:** Созданный бот и его токен (`TELEGRAM_BOT_TOKEN`).
3.  **Telegram Chat ID:** ID вашего личного чата или группы для получения отчетов (`TELEGRAM_CHAT_ID`).
4.  **LLM API Key:** Ключ доступа к API языковой модели (например, OpenAI, Anthropic, или Gemini), который будет использоваться в узле **LLM Agent**.

## 3. Пошаговая настройка

### Шаг 3.1: Импорт рабочего процесса

1.  Скачайте файл **n8n_trader_agent_workflow.json**.
2.  В интерфейсе n8n перейдите в раздел "Workflows".
3.  Нажмите "New" -> "Import from JSON" и загрузите файл.

### Шаг 3.2: Настройка Telegram

1.  В n8n создайте новое **Credential** для Telegram.
2.  Введите ваш `TELEGRAM_BOT_TOKEN`.
3.  Откройте узлы **Telegram: Ask for Clarification** и **Telegram: Send Confident Idea**, а также **Telegram: Send Final Daily Report**.
4.  В поле **Chat ID** замените выражение `={{ $env.TELEGRAM_CHAT_ID }}` на ваш фактический Chat ID (например, `-123456789`).

### Шаг 3.3: Настройка LLM Agent (База знаний)

Узел **LLM Agent (Trade Idea Generation)** является сердцем системы. Он содержит всю вашу торговую стратегию.

1.  Откройте файл **trader_agent_system_prompt.md**.
2.  Скопируйте его содержимое.
3.  В узле **LLM Agent (Trade Idea Generation)** вставьте скопированный текст в поле **System Prompt**.
4.  **Важно:** Убедитесь, что вы выбрали подходящую модель (например, `gpt-4o` или `gemini-2.5-flash`) и настроили соответствующий **Credential** с вашим API-ключом.

### Шаг 3.4: Настройка Технического Анализа (TA)

Узел **Technical Analysis (Code Node)** — это место, где происходит предварительная обработка данных и расчет индикаторов.

1.  **Текущая реализация:** В импортированном JSON-файле этот узел содержит упрощенный JavaScript-код для демонстрации.
2.  **Реализация Python:** Для полноценного анализа, включая волны Эллиотта и многотаймфреймовый анализ, вам необходимо заменить содержимое этого узла на более сложный код, используя Python-скрипт **n8n_ta_processor.py** как основу.
    *   **Рекомендация:** Используйте узел **Execute Command** или **Code (Python)**, если ваша версия n8n его поддерживает, для запуска Python-скрипта.
    *   **Задача пользователя:** Расширить логику в **n8n_ta_processor.py** для:
        *   Получения исторических данных (1H, 4H, Daily) для каждого тикера (через дополнительный HTTP Request к MOEX ISS или другому источнику).
        *   Реализации логики волнового анализа Эллиотта и паттернов.

### Шаг 3.5: Настройка Триггеров

1.  **Cron Trigger (Daily Report):** Установлен на 09:30 МСК. Вы можете изменить это время, если необходимо.
2.  **Webhook Trigger (Q&A/TV Signal):**
    *   Активируйте этот узел. n8n сгенерирует уникальный URL (например, `https://your.n8n.url/webhook/telegram-qa`).
    *   Этот URL используется для:
        *   **TradingView:** Настройте оповещение (Alert) в TradingView, которое будет отправлять данные о тикерах на этот Webhook.
        *   **Telegram Q&A:** Вы можете настроить отдельный Telegram-бот или использовать этот Webhook для отправки текстовых запросов агенту.

## 4. Механизм контроля неопределенности

В узле **Check Uncertainty (> 0.1)** реализовано ваше требование:

*   **Условие:** Если вероятность трендового движения, рассчитанная LLM, меньше 90% (т.е. неопределенность > 0.1), рабочий процесс идет по ветке **False**.
*   **Действие:** Агент отправляет в Telegram сообщение с предупреждением и задает конкретный вопрос, который LLM сформулировал в поле `justification.key_risks`, требуя от вас дополнительной информации для принятия решения.

## 5. Дополнительные файлы

| Файл | Описание | Примечание |
| :--- | :--- | :--- |
