# 6 классических проблем и их решения

Из реальной практики. Все эти ошибки я уже сделал — теперь у тебя есть готовые решения.

---

## Проблема 1: Агент запускается, но молчит

**Симптом:** Cron отрабатывает (видно в логе), но в Telegram ничего не приходит.

**Причина:** Скрипт запускается в окружении cron, где нет PATH и переменных окружения.
Claude не находится по пути, скрипт тихо падает.

**Решение:**
```bash
#!/usr/bin/env bash

# ОБЯЗАТЕЛЬНО в начале каждого скрипта для cron:
export PATH="/usr/local/bin:/usr/bin:/bin:$HOME/.local/bin"
export HOME="/root"  # или твой домашний каталог

# Проверить где находится claude:
# which claude  →  /usr/local/bin/claude
# и убедиться что этот путь в PATH выше
```

**Как диагностировать:**
```bash
# Запусти скрипт вручную и смотри что происходит
bash -x ~/claudeclaw/scripts/my_task.sh 2>&1 | head -50
```

## Проблема 2: Агент делает задачу несколько раз подряд

**Симптом:** В Telegram приходит 3-5 одинаковых сообщений вместо одного.

**Причина:** Cron запустил новый экземпляр пока предыдущий ещё работал.
Так бывает если задача занимает больше времени чем интервал между запусками.

**Решение — lock-файл:**
```bash
LOCK=/tmp/my-task.lock

# В начале скрипта:
if [ -f "$LOCK" ]; then
  echo "$(date) -- Already running, skipping" >> "$LOG"
  exit 0
fi
touch "$LOCK"

# Автоматическое удаление при любом выходе:
trap 'rm -f "$LOCK"' EXIT

# ... дальше твоя задача ...
```

**Если lock завис** (скрипт упал и не удалил lock):
```bash
# Удалить вручную:
rm -f /tmp/my-task.lock
```

## Проблема 3: Агент сжигает токены за ночь

**Симптом:** Утром видишь что за ночь улетело 20-30% месячного лимита.

**Причина:** Агент пошёл в бесконечный цикл или задача оказалась намного сложнее чем ожидалось.

**Решение — двойная защита:**
```bash
# 1. Жёсткий timeout (в секундах):
timeout 180 claude --agent my-agent -p "..." >> "$LOG" 2>&1

# 2. Ограничение шагов:
timeout 180 claude \
  --agent my-agent \
  --max-turns 5 \
  -p "..." >> "$LOG" 2>&1

# Правило: время_задачи × 3 = timeout
# Если задача обычно 30 сек → timeout 90 сек
# Если задача обычно 60 сек → timeout 180 сек
```

## Проблема 4: Результат есть, но формат не тот

**Симптом:** Агент что-то прислал, но не в том виде что ожидал. Каждый раз по-разному.

**Причина:** Промпт был размытым при ручном тестировании, агент угадывал формат.
В автономном режиме без обратной связи угадывает иначе.

**Решение — явный шаблон в промпте:**

Плохо:
```
Проанализируй файлы и отправь отчёт
```

Хорошо:
```
Проанализируй файлы. Отправь в Telegram ТОЛЬКО в таком формате:

---
Отчёт — {YYYY-MM-DD}
Файлов обработано: {N}
Найдено: {список через запятую или "ничего"}
Статус: OK / ВНИМАНИЕ
---

Не добавляй ничего сверх этого шаблона.
```

## Проблема 5: Задача работала неделю, потом сломалась

**Симптом:** Cron срабатывает, агент получает задачу, но возвращает "не понимаю что делать"
или делает что-то не то.

**Причины:**
- Обновился CLAUDE.md — контекст изменился
- Переименовали папку или файл
- Изменился формат данных которые агент читает

**Решение — самодостаточный промпт:**

Плохо (полагается на внешний контекст):
```
Сделай аудит как мы обычно делаем, ты знаешь как
```

Хорошо (всё внутри промпта):
```
Ты агент-аудитор. Выполни эти конкретные шаги:
1. ls ~/.claude/agents/ — получи список агентов
2. Прочитай ~/obsidian-vault/ClaudeClaw/changelog.md
3. Найди агентов которые есть в списке но не в changelog
4. Отправь список в Telegram: "Не задокументировано: {список}"
Не спрашивай уточнений. Выполни и завершись.
```

## Проблема 6: Агент начинает "творить"

**Симптом:** Агент не просто выполнил задачу — он "помог" переименовать папку,
удалил "лишние" файлы, обновил "устаревший" промпт.

**Причина:** Не задан явный scope действий.

**Решение — явный запрет в начале промпта:**
```
ВАЖНО: Только читай. Не изменяй и не удаляй файлы.
Не переименовывай папки. Только анализ и отчёт.
Если видишь что-то что "стоит исправить" — только укажи это в отчёте,
не правь самостоятельно.
```

**Дополнительная защита — ограниченный набор инструментов:**

В файле агента (`~/.claude/agents/my-agent.md`):
```markdown
---
name: my-agent
tools: Bash, Read, Glob, Grep
---
```

Не давай агенту `Write` и `Edit` если задача только на чтение и анализ.

## Быстрая диагностика

```bash
# Посмотреть что делал cron за последние часы:
grep "my-task" /var/log/syslog | tail -20

# Посмотреть лог скрипта:
tail -50 ~/claudeclaw/workspace/tmp/my-task.log

# Проверить что cron вообще работает:
systemctl status cron

# Проверить что задача добавлена:
crontab -l
```
