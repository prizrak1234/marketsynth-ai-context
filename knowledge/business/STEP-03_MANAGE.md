# Шаг 3 — Управление задачами

## Основные команды

### Список всех задач
```bash
node dist/schedule-cli.js list
```

Показывает: ID, статус, промпт (первые 50 символов), расписание, следующий и последний запуск.

### Приостановить задачу
```bash
node dist/schedule-cli.js pause ID_ЗАДАЧИ
```

Полезно: уехал в отпуск, временно не нужна задача.

### Возобновить задачу
```bash
node dist/schedule-cli.js resume ID_ЗАДАЧИ
```

### Удалить задачу
```bash
node dist/schedule-cli.js delete ID_ЗАДАЧИ
```

ID задачи берёте из вывода команды `list`.

## Шпаргалка по cron-расписанию

```
* * * * *
│ │ │ │ └── день недели (0-7, 0 и 7 = воскресенье)
│ │ │ └──── месяц (1-12)
│ │ └────── день месяца (1-31)
│ └──────── час (0-23)
└────────── минута (0-59)
```

### Частые паттерны

| Расписание | Cron | Пример использования |
|---|---|---|
| Каждый день в 9:00 | `0 9 * * *` | Утренний дайджест |
| Каждый понедельник в 9:00 | `0 9 * * 1` | Планирование недели |
| Каждое воскресенье в 10:00 | `0 10 * * 0` | Итоги недели |
| Каждые 4 часа | `0 */4 * * *` | Мониторинг |
| Каждые 30 минут | `*/30 * * * *` | Частый мониторинг |
| Пн-Пт в 9, 13, 17 | `0 9,13,17 * * 1-5` | Рабочий мониторинг |
| 1-е число каждого месяца | `0 9 1 * *` | Месячный отчёт |
| Каждую пятницу в 17:00 | `0 17 * * 5` | Итоги пятницы |

### Сервис для проверки cron-строки
https://crontab.guru — вставляете строку и видите расписание человеческим языком.

## Советы по промптам для планировщика

**Хорошо:**
```
"Проверь папку inbox/, если есть новые файлы — обработай и сообщи.
Если папка пустая — промолчи."
```

**Плохо:**
```
"Посмотри что там"
```

**Правила:**
1. Конкретно что проверить / что сделать / что сообщить
2. Добавляйте условие "если нечего — промолчи" чтобы не спамить
3. Длинные задачи лучше оформлять скриптом: `node scripts/имя.js`
4. Тестируйте промпт вручную в боте перед добавлением в scheduler
5. Указывайте абсолютные пути к файлам: `/root/claudeclaw/...`

## Troubleshooting

**Задача не запускается в нужное время:**
- Проверьте что pm2-процесс online: `pm2 list`
- Время на сервере в UTC. Если хотите московское — прибавьте 3 часа
- Проверьте cron-строку через https://crontab.guru

**Задача запускается но бот не отвечает:**
- Проверьте что CHAT_ID правильный
- Посмотрите логи: `pm2 logs claudeclaw --lines 50`

**Как узнать время на сервере:**
```bash
date
```

**Перевод времени:** сервер обычно в UTC. Московское = UTC+3.
- Хотите задачу в 9:00 МСК → укажите `0 6 * * *` (UTC)
- Хотите в 9:00 UTC → укажите `0 9 * * *`

## Как изменить задачу

Команды `edit` нет. Чтобы изменить промпт или расписание:

```bash
# 1. Посмотрите ID задачи
node dist/schedule-cli.js list

# 2. Удалите старую
node dist/schedule-cli.js delete ID_ЗАДАЧИ

# 3. Создайте новую с изменёнными параметрами
node dist/schedule-cli.js create "новый промпт" "новый cron" CHAT_ID
```

Это занимает 10 секунд. Проще, чем кажется.

## Просмотр логов планировщика

Все запуски задач пишутся в pm2 логи. Полезно для отладки.

```bash
# Последние 50 строк логов
pm2 logs claudeclaw --lines 50

# Только строки связанные со scheduler
pm2 logs claudeclaw --lines 100 | grep -i "scheduler\|schedule\|scheduled"

# Следить за логами в реальном времени
pm2 logs claudeclaw --raw
```

Строки вида `[Scheduler] Running task ID=3 ...` означают что задача запустилась.

## Полный текст промпта задачи

`list` показывает только первые 50 символов промпта. Чтобы увидеть полный текст — задайте вопрос агенту напрямую в Telegram:

```
покажи полный промпт задачи ID=3
```

Или посмотрите в базе данных планировщика:

```bash
# Найти файл базы данных
ls /root/claudeclaw/data/

# Посмотреть задачи напрямую (если SQLite)
sqlite3 /root/claudeclaw/data/scheduler.db "SELECT id, prompt, cron FROM scheduled_tasks;"
```
