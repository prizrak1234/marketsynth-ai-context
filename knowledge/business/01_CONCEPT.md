# Шаг 1: Концепция системы

Прими эту архитектуру как базовую для внедрения генерации изображений.

## Главный принцип

Для генерации изображений по умолчанию используется **skill-first архитектура**, а не отдельный агент на каждый запрос.

## Почему так

- простой запрос идет в один поток
- skill дешевле по токенам, чем отдельный агент
- runtime-логика остается предсказуемой
- сложные визуальные задачи можно эскалировать отдельно

## Граница ответственности

### Skill

Отвечает за:
- распознавание image-задачи
- извлечение параметров из запроса
- адаптацию короткого пользовательского промпта
- выбор модели
- решение: простой путь или эскалация

### Runtime layer

Отвечает за:
- вызов API
- polling
- скачивание изображения
- сохранение в `workspace/output/images/`
- проверку, что файл существует и не пустой

### Image agent

Подключается только если:
- нужно несколько вариантов
- есть image-to-image
- нужна серия изображений
- нужно работать с несколькими референсами
- нужны итерации и сложные правки

## Обязательное поведение

1. Не отправляй пользовательский короткий промпт в API как есть.
2. Всегда нормализуй его до качественного image prompt.
3. Сохраняй итоговые файлы локально.
4. Не заявляй успех, пока файл не скачан и не проверен.
5. Если задача сложная, эскалируй в visual-agent вместо костылей в skill.
