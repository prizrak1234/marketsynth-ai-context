# ClaudeClaw — полная система генерации контента

> "Если вы думаете, что установите пару скиллов для своего Claude Code и он вдруг начнёт создавать бомбический контент -- вы ошибаетесь."

Это руководство описывает реальную систему создания контента, которую Игорь Зуевич строит вместе с ИИ-агентом ClaudeClaw. Не промпты. Не шаблоны. Система.

---

## Почему скиллы сами по себе не работают

ИИ без контекста пишет generic-слоп. Красивый, грамотный, никакой.

Чтобы ИИ писал В ВАШЕМ стиле, ему нужно:
1. **Архив ваших текстов** -- не 5 примеров, а сотни
2. **Размеченные паттерны** -- что сработало, что нет
3. **Обратная связь** -- какие посты зашли, какие провалились
4. **Память между сессиями** -- чтобы не объяснять всё заново

Скилл "напиши пост" -- это 5% системы. Остальные 95% -- это инфраструктура.

## Шаг 1: Загрузка архива контента в Obsidian

Без архива нет системы. Вот что нужно:

### 1.1 Выгрузка постов из Telegram

Telegram Desktop → Экспорт данных → JSON. Получаем все посты канала.

### 1.2 Парсинг и сохранение

Каждый пост становится отдельным `.md` файлом с YAML frontmatter:

```yaml
---
id: 1935
date: 2026-03-23
author: Igor
source: Telegram
channel: Канал Игоря Зуевича
reactions: "👍11 👏6 🔥5 ❤2"
topics: [ИИ, безопасность]
formats: [мнение]
tags: [ИИ, Claude, безопасность, мнение]
---
```

**Критично:** `reactions` -- это обратная связь. По ним видно что зашло.

### 1.3 Формат имени файла

```
YYYY-MM-DD_NNNN_Первые слова поста.md
```

Где `NNNN` -- порядковый номер поста.

### 1.4 Структура папок

```
Telegram/Канал/
  ├── Текст/    (текстовые посты)
  └── Видео/    (видео-посты)
```

> У нас сейчас: 206 текстовых + 220 видео-постов. Это база, на которой ИИ учится стилю.

## Шаг 2: Создание MOC (Map of Content) -- навигация для ИИ

MOC -- это индексы по тегам. Без них ИИ-агент не может быстро найти нужные посты.

### 2.1 Какие MOC нужны

**По темам:**
- MOC-ИИ.md (194 поста)
- MOC-n8n.md (144 поста)
- MOC-продажи.md (113 постов)
- MOC-реклама.md (95 постов)
- MOC-мышление.md (50 постов)

**По форматам (это ключевое!):**
- MOC-формат-провокация.md (133 поста)
- MOC-формат-совет.md (92 поста)
- MOC-формат-кейс.md (88 постов)
- MOC-формат-история.md
- MOC-формат-мнение.md
- MOC-формат-анонс.md

### 2.2 Автогенерация MOC

Скрипт `generate-moc.js` сканирует весь vault каждый день в 7:00 и автоматически создаёт MOC по тегам из frontmatter.

Результат: 118 MOC-страниц, все заметки проиндексированы.

### 2.3 Зачем это ИИ-агенту

Когда агент получает задачу "напиши пост про ИИ-агентов в формате провокации":
1. Открывает `MOC-ИИ.md` -- видит 194 поста на тему ИИ
2. Открывает `MOC-формат-провокация.md` -- видит 133 провокационных поста
3. Находит пересечение: посты про ИИ в формате провокации
4. Читает 3-5 лучших (по reactions) как референс
5. Пишет в том же стиле, но с новым содержанием

Без MOC агент пишет вслепую.

## Шаг 3: Таблица паттернов -- что реально работает

Это самый недооценённый элемент. Большинство людей генерируют контент без анализа того, что уже сработало.

### 3.1 MOC-Threads -- таблица паттернов

```markdown
## Паттерны которые работают

| Тип хука           | Тип концовки           | Угол                                     | Пост |
|---------------------|------------------------|------------------------------------------|------|
| парадокс            | открытый вопрос        | переворот знакомого понятия              | [[]] |
| цифра-парадокс      | незакрытое утверждение  | кликнуть vs доверять                     | [[]] |
| разворот ожидания   | незакрытое утверждение  | не РФ, а глобальный кризис               | [[]] |
```

### 3.2 Три колонки, которые всё меняют

**Тип хука** (как начинается пост):
- Парадокс: "Восстание машин уже не про роботов"
- Цифра: "15 минут. Столько ушло..."
- Разворот ожидания: "Все думали, что..."
- Провокация: "Влюбляться в инструмент -- самый дорогой способ..."

**Тип концовки** (как заканчивается):
- Открытый вопрос: "Страшно? Или наконец-то удобно?"
- Незакрытое утверждение: "С тех пор у меня правило: всё, от чего зависишь, должно быть заменяемо."
- НЕ работает: готовый вывод, слоган, мораль

**Угол** (в чём неожиданность):
- Не "новая фича ИИ" → а "смена категории продукта"
- Не "Claude забанил РФ" → а "глобальный кризис масштабирования"
- Не "я подключил нового бота" → а "всё, от чего зависишь, должно быть заменяемо"

### 3.3 Как агент использует паттерны

При генерации Threads-поста агент:
1. Читает `MOC-Threads.md`
2. Видит какие хуки и концовки работают
3. Применяет паттерн к новой теме
4. Предлагает 3 варианта с разными комбинациями хук + концовка

## Шаг 4: Pipeline создания контента

### 4.1 Telegram → Threads (основной flow)

```
Телеграм-пост (длинный, авторский)
        │
        ▼
  Сохранение в Obsidian
  (frontmatter + связанные посты)
        │
        ▼
  ClaudeClaw генерирует 3 варианта Threads
  (каждый с разным хуком и концовкой)
        │
        ▼
  Игорь выбирает или правит
        │
        ▼
  Одобренный пост → Threads/YYYY-MM-DD_slug.md
  MOC-Threads обновляется (новый паттерн в таблицу)
```

### 4.2 YouTube → контент (анализ + генерация)

```
YouTube URL
    │
    ▼
youtube-analyzer агент
(n8n webhook → транскрипция → анализ)
    │
    ▼
Заметка в Obsidian/YouTube/
(summary, ключевые моменты, takeaways)
    │
    ▼
content-writer агент x3 параллельно
(Threads + Instagram + Reels варианты)
```

### 4.3 Идея → полный цикл

```
Идея / тема
    │
    ▼
Vault-first search:
  MOC → grep → связанные заметки
    │
    ▼
Контекст: что уже писали на эту тему?
Какие углы уже использовали?
    │
    ▼
Генерация с новым углом
(не повторять то что уже было)
```

## Шаг 5: Стиль автора -- чему учить ИИ

### 5.1 Что выявлено из 206 постов Игоря Зуевича

**Голос:**
- Прямой, без воды
- Личные истории как доказательства ("В 2011 году мне не продлили аренду...")
- Нет менторского тона -- разговор на равных
- Эмоциональные маркеры: "Короче", "Капец", "Херачу"
- Вопросы к читателю, но без кликбейта

**Структура постов:**
- Хук в первой строке (факт, цифра, парадокс)
- Личная история или кейс в середине
- Незакрытый конец (вопрос или утверждение без морали)

**Что НЕ делать:**
- Обобщения в начале ("В мире ИИ всё меняется...")
- Готовые выводы вместо вопросов
- Слоганы вместо мыслей
- Много английских слов
- Эмодзи ради эмодзи (использовать точечно)

### 5.2 Как кодифицировать стиль для ИИ

Стиль нельзя описать промптом в 5 строк. Стиль передаётся через:
1. **Примеры** -- агент читает реальные посты перед генерацией
2. **Паттерны** -- таблица хуков и концовок из одобренных постов
3. **Антипаттерны** -- "Что не работает" в MOC-Threads
4. **Обратная связь** -- после правок человеком агент видит разницу между черновиком и финалом

## Шаг 6: Обратная связь и обучение системы

### 6.1 Цикл обучения

```
Генерация → Правки человека → Сохранение → Обновление паттернов
     ↑                                              │
     └──────────────────────────────────────────────┘
```

Каждый одобренный пост:
- Добавляется в `MOC-Threads.md` с типом хука и концовки
- Связывается с исходным постом через [[wikilinks]]
- Становится примером для будущих генераций

### 6.2 Что упускают 99% людей

**Нет архива = нет стиля.** ИИ пишет в среднестатистическом стиле.

**Нет паттернов = нет повторяемости.** Удачный пост остаётся случайностью.

**Нет обратной связи = нет улучшения.** Система не учится на ошибках.

**Нет cross-linking = нет контекста.** Агент не видит что уже писали на эту тему и повторяется.

### 6.3 Роль Obsidian

Obsidian -- не просто хранилище файлов. Это:
- **Долгосрочная память ИИ-агента** (vault-first search)
- **Навигация** (MOC по тегам -- 118 индексов)
- **Граф связей** (cross-linking между заметками)
- **Аналитика паттернов** (таблицы в MOC)

Без Obsidian (или аналога) ИИ-агент каждую сессию стартует с нуля.

## Шаг 7: Мультиагентная команда

### 7.1 Зачем несколько агентов

Один агент = одна точка отказа. Если Claude ляжет -- контент останавливается.

Текущая команда:
- **ClaudeClaw** (Claude Code) -- основной агент
- **CodexClaw** (OpenAI Codex) -- резервный агент
- Планы: Gemini, кто-то из китайских моделей

### 7.2 Как агенты обмениваются знаниями

```
agent-memory.md -- общий файл памяти
    │
    ├── ClaudeClaw пишет: "Паттерн Х сработал для Threads"
    ├── CodexClaw читает и применяет
    └── Каждые 12 часов: dream.sh консолидирует
```

### 7.3 Как новый агент входит в систему

1. Читает CLAUDE.md (инструкции)
2. Читает agent-memory.md (накопленные знания)
3. Читает MOC-Threads.md (паттерны контента)
4. Всё. Готов к работе за 15 минут.

## Чеклист: минимальная система для генерации контента

- [ ] **Архив постов в Obsidian** с frontmatter (id, date, topics, formats, tags, reactions)
- [ ] **MOC по темам и форматам** (автогенерация по тегам)
- [ ] **Таблица паттернов** (какие хуки и концовки работают)
- [ ] **Стиль автора** кодифицирован через примеры, не через описание
- [ ] **Pipeline** Telegram → Obsidian → Threads/Instagram/Reels
- [ ] **Обратная связь** одобренные посты обновляют паттерны
- [ ] **Cross-linking** заметки связаны между собой
- [ ] **Vault-first search** агент ищет в vault перед генерацией
- [ ] **agent-memory.md** знания сохраняются между сессиями
- [ ] **Резервный агент** на случай падения основного

## Что можно улучшить дальше

1. **Авто-анализ reactions** -- скрипт который собирает реакции с Telegram API и обновляет frontmatter. Посты с высокими реакциями автоматически попадают в "лучшие примеры".

2. **A/B тестирование хуков** -- генерировать 2 варианта, публиковать по очереди, сравнивать engagement.

3. **Авто-кросс-постинг** -- один пост адаптируется под 3-4 платформы автоматически.

4. **Сезонный анализ** -- какие темы и форматы лучше работают в разное время.

5. **Voice-to-content** -- наговорить мысль голосом → транскрипция → агент оформляет в пост.
